## Two assessment flows coexist

| Flow | Actual coverage | Entry and result |
| --- | --- | --- |
| **Quick Screening** (`quick_screening`) | English/Spanish **grammar only**; A1–B2, 6-item adaptive batches, policy minimum 12 usable answers and maximum 30 issued questions. A learner can stop earlier with a partial result. The full target Quick mode (grammar + vocabulary + reading) is absent. | New onboarding selection starts it through `POST /learning/path/tests` with `assessmentType`; the same test/answer tables and `GET /learning/path/tests/:id` are reused. [RuntimeMode/AvailableModes](../../apps/learning/backend/internal/learningpath/assessment/modes.go), [StartAssessment](../../apps/learning/backend/internal/learningpath/commands/assessment.go), [UI selection](../../apps/learning/frontend/src/features/assessment/start.tsx). |
| **Legacy placement/final tests** | AI-generated multiple-choice grammar, vocabulary, reading at each CEFR rung. This is a separate older measurement policy and has no canonical item evidence. | `POST /learning/path/tests` without assessment type (placement), `POST /learning/path/final-tests`; AI judge decides climb/stop. [Start/generate/judge](../../apps/learning/backend/internal/learningpath/commands/test.go), [legacy prompts](../../apps/learning/backend/internal/learningpath/commands/testgen.go). |
| Full, Skill, diagnostic, reassessment | **No runnable mode.** Constants, schema enum values, format names, blueprint validation and a pure section aggregation helper exist; no independent section lifecycle/storage/evaluator/UI. | `RuntimeMode` rejects every mode except Quick; [frontend choices](../../apps/learning/frontend/src/features/assessment/start.tsx) disable Full/Skill. [Tests](../../apps/learning/backend/internal/learningpath/assessment/assessment_test.go) assert this. |

The backend [capability endpoint](../../apps/learning/backend/internal/learningpath/controller_assessment.go) returns only Quick/grammar for `en` and `es`; other languages return none. The frontend currently also has a hard-coded `en`/`es` [availability check](../../apps/learning/frontend/src/features/assessment/availability.ts), so dynamic use of that capability response is still incomplete. Manual/self-reported starting level and start-from-scratch are separate onboarding paths, **not** assessment evidence ([ChooseLevel](../../apps/learning/backend/internal/learningpath/commands/test.go)).

## Quick Screening lifecycle

1. [Onboarding selection](../../apps/learning/frontend/src/features/assessment/screen.tsx) requests `quick_screening`, optionally with a learner-selected A1–B2 start. [StartAssessment](../../apps/learning/backend/internal/learningpath/commands/assessment.go) defaults to A2, upserts/reuses the teacher profile, resumes an open assessment of that type, rejects a simultaneous active program, snapshots the policy into `learning_path_tests.assessment_policy`, and prepares the first batch. A configured user AI agent is required only if a batch needs generated fallback items.
2. [Bank](../../apps/learning/backend/internal/learningpath/assessment/bank.txt) has **48 curated questions per language, 12 per level, mapped to 24 grammar rule IDs**. [Bank()](../../apps/learning/backend/internal/learningpath/assessment/blueprint.go) checks every entry against the embedded Rule Book and copies its localized `goal` as objective. [Select()](../../apps/learning/backend/internal/learningpath/assessment/blueprint.go) prioritizes category coverage and unseen/reduced-exposure items. A batch has six slots, one target per rule ID; previously asked prompt fingerprints are queried across the teacher profile. When a slot's bank wording was seen, the slot still carries its canonical item/format but asks AI to create fresh wording.
3. [AI generation](../../apps/learning/backend/internal/learningpath/commands/assessment_items.go) uses `screeningItemPrompt`: the backend sends `{language, slots:[{knowledgeItemKey,category,learningObjective,skill,difficultyBand,questionType}], alreadyAsked}`. The model may return only `{questions:[{text,prompt,options,answers}]}` in slot order. It cannot choose the ID, band, skill, verdict or evidence. `diagnosticContent.UnmarshalJSON` disallows unknown top-level fields; `assessment.Validate` checks answer/options/context/format, count, length and duplicate fingerprints. [Agent.completeJSON](../../apps/learning/backend/internal/learningpath/commands/agent.go) extracts JSON, runs semantic validation and retries once on malformed output. If generation remains unavailable, the assessment becomes failed (no evidence) or partial (some evidence); throttling is surfaced for retry.
4. [insertScreeningQuestion](../../apps/learning/backend/internal/learningpath/commands/assessment_items.go) re-resolves the canonical rule, lazily upserts `kb_items`, shuffles options, and persists question text, hidden key/alternatives, canonical UUID/key, category, objective, format, origin, fingerprint, batch and a question version UUID. These are issued-question snapshots, not content revisions. The current bank formats are multiple choice, open gap, error correction, sentence transformation, plus one English `reading_comprehension` and one Spanish `vocabulary_in_context`; those two remain **grammar questions**. Other format constants (`writing`, `listening`, `speaking`, `pronunciation`) are not accepted by the current content validator or issued by Quick.
5. [answerAssessment](../../apps/learning/backend/internal/learningpath/commands/assessment_answers.go) locks the test, accepts 1–6 answers from the active batch, supports idempotent re-submission of an identical answer, and rejects changes to an answered item. [Grade](../../apps/learning/backend/internal/learningpath/assessment/blueprint.go) compares normalized text with a server-held answer key, allowing authored alternatives/partial alternatives. It writes an answer and one append-only `learning_evidence` row in one transaction, including score, weight, origin-derived weight, assistance flag and canonical `item_id`. Skips/invalid keys do not supply usable measurement. **Quick evidence is not folded into `learner_item_state` mastery or review schedule**; the tracked exercise path does that separately ([recordEvidence](../../apps/learning/backend/internal/learningpath/commands/loop.go)).
6. [Decide](../../apps/learning/backend/internal/learningpath/assessment/policy.go) handles six-question batches. A valid upward signal needs at least two categories, two curated observations, and at least 5/6 correct; a downward signal needs at least 4/6 incorrect. Batches move one band; conflicting/inconclusive batches stay. A bracket between adjacent positive/negative bands, or a twice-confirmed A1 floor/B2 ceiling, gives a provisional range only after at least 12 usable answers across three categories. It stops on sufficient boundary or 30 total answers. Learner `complete`/`cancel`, question-generation failure and interrupted preparation have explicit states.
7. [Summarize](../../apps/learning/backend/internal/learningpath/assessment/policy.go) persists an `assessment_result` JSON with evidence sufficiency, provisional difficulty range, one grammar section, item outcomes, strengths, suspected/strong gaps, recommended checks/objectives and explicit unassessed skills. `demonstrated` for a rule requires at least two correct, including non-recognition and curated evidence, and no errors/partials. Strong gap requires two curated-supported incorrect with no correct; one incorrect supports only a suspected gap. An item without observations remains `not_assessed`. This is **not mastery or certified CEFR proficiency**. `level_reached` remains a compatibility label for path creation: lower range bound, or A1 if there is no range ([finishAssessment](../../apps/learning/backend/internal/learningpath/commands/assessment.go)).
8. `pause`, `resume`, `complete`, `cancel` use the same locked row; results are available via `GET /learning/path/tests/:id/results` ([AssessmentAction](../../apps/learning/backend/internal/learningpath/commands/assessment.go), [controller](../../apps/learning/backend/internal/learningpath/controller_assessment.go)). Resume restarts an interrupted `evaluating` batch. There is no separate section table; the current one-section result is embedded in JSON.

### Legacy behavior that must not be attributed to Quick

[Legacy `testQuestionsSystem` and `testJudgeSystem`](../../apps/learning/backend/internal/learningpath/commands/testgen.go) ask AI for 8 placement or 10 final four-option questions per level across grammar/vocabulary/reading, then an AI verdict of `climb` or `stop`. [placement.Grade](../../apps/learning/backend/internal/learningpath/placement/ladder.go) checks selected option against the generated key. The prompt asks for CEFR matching, but no canonical item target, calibrated question difficulty, persisted item-level evidence or independent skill estimate is enforced. Its A1–C2 ladder and AI judgement are not the deterministic Quick policy. The old `final` test remains for program completion; Quick has no equivalent final check.

## Persistence and learning path integration

[Migration 0037](../../apps/learning/backend/migrations/0037_adaptive_assessment.sql) extends `learning_path_tests`, `_questions`, `_answers` and the V1 `learning_evidence` table; no new independent assessment section or item bank table is added. [Migration 0036](../../apps/learning/backend/migrations/0036_learning_loop.sql) defines `kb_items`, evidence, derived `learner_item_state`, and typed activities. SQL write/read contracts are in [learning_assessment.sql](../../apps/learning/backend/queries/learning_assessment.sql). A teacher is the profile root; there is not yet a server-owned profile with per-skill confidence/history APIs ([profile roadmap](../learning/IMPLEMENTATION_PLAN.md)).

For Quick, [BuildProgram](../../apps/learning/backend/internal/learningpath/commands/build.go) accepts completed or partial screening, and [Analyze.Handle](../../apps/learning/backend/internal/learningpath/commands/analyze.go) calls [analyzeScreening](../../apps/learning/backend/internal/learningpath/commands/assessment_plan.go). The deterministic planner uses canonical Rule Book gap/check IDs, ten hard-coded prerequisite targets per language, skips `demonstrated` bank items, then adds library topics for explicitly unassessed skills; goal/interests tags and weekly hours affect order/size. It copies authored topic content to a **new** program. It does not revise an active path; an active program prevents building another. Reset/archival preserves prior paths, but there is no path revision/diff model or replay of completed activity state into a newly generated path. Legacy tests use AI selection of validated catalog IDs via [planSystem](../../apps/learning/backend/internal/learningpath/commands/plan.go); unsupported pairs may get fully AI-written programs without canonical item linkage.

Tracked program exercises generate content from a topic and persist answer attempts; attributable answers write evidence and update mastery/review schedule ([exercise](../../apps/learning/backend/internal/learningpath/commands/exercise.go), [loop](../../apps/learning/backend/internal/learningpath/commands/loop.go)). `learning_activities` has types `learn/practice/review/apply/assess`, but the V1 runtime materializes only practice/review; an assessment question is not a typed learning activity ([D-026](../learning/DECISIONS.md), [V1 status](../learning/IMPLEMENTATION_STATUS.md)). Free Rule Book practice writes neither durable history nor evidence ([D-107/D-025](../learning/DECISIONS.md)).

## Actual AI and audio capabilities

The [LLM client](../../apps/learning/backend/internal/llm/llm.go) supports **text completion** with Anthropic, OpenAI, DeepSeek and Kimi using user-supplied AI settings. JSON is requested in prompts and parsed/validated in the application; provider-native constrained structured output is **not** integrated. Text evaluation exists for legacy AI examiner and some exercise review ([test judge](../../apps/learning/backend/internal/learningpath/commands/testgen.go), [attempt review](../../apps/learning/backend/internal/learningpath/commands/attempt.go)), but there is no calibrated writing rubric in Assessment Engine. [TTS provider](../../apps/learning/backend/internal/learningaudio/provider.go) generates MP3 for exercise/word audio, which the frontend can [play](../../apps/learning/frontend/src/features/path/components/play-button.tsx). [Browser speech recognition](../../apps/learning/frontend/src/features/path/speech.ts) yields a transcript for a `speak` practice item; there is no recorded-audio upload, persisted audio assessment, audio-aware speaking/pronunciation rubric, or transcript-independent pronunciation analysis. Existing audio is **not** an assessment listening bank with hidden transcript and provenance.
