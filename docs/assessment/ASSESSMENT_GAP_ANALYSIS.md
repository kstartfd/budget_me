## Architectural decisions and constraints

[D-024](../learning/DECISIONS.md) prioritizes a vertical learning loop; V1 is verified. [D-025](../learning/DECISIONS.md) separates evidence source from practice mode and preserves [D-107](../learning/DECISIONS.md) transient Rule Book practice. [D-026](../learning/DECISIONS.md) persists activities outside sessions. [D-034](../learning/DECISIONS.md) authorizes the bounded deterministic grammar Quick slice; [D-035–D-037](../learning/DECISIONS.md) make Quick/Full/Skill configurable modes of one engine, require skill-specific evidence gates and sectioned Full, without declaring those workflows implemented. [D-032](../learning/DECISIONS.md) requires independent evidence before mastery. Open content decisions [D-008, D-013, D-015](../learning/DECISIONS.md) affect KB authoring/versions, prerequisites and source/licences; [D-022](../learning/DECISIONS.md) affects the meaning of the compatibility `levelReached` label. See the decision log for statuses and exact wording rather than treating this summary as an ADR replacement.

The working tree contains Quick code, migration 0037, status/docs and onboarding changes. [Implementation Status](../learning/IMPLEMENTATION_STATUS.md) says P3-14 shared blueprint is `IN_PROGRESS`, grammar Quick is locally verified, and P1/P2/P4 are not started as **full phases**. The [older assessment roadmap](../learning/ASSESSMENT_ENGINE.md) sketches posterior calibration, while the runtime uses heuristic `Decide`; [KB documentation](../learning/KNOWLEDGE_BASE.md) lacks the new small code-only prerequisite map. [DATA_MODEL.md](../learning/DATA_MODEL.md) also has pre-0036 baseline wording. These are scope/snapshot differences, not evidence of completed target phases.

**Rollback risk:** the `Down` half of [migration 0037](../../apps/learning/backend/migrations/0037_adaptive_assessment.sql) explicitly deletes assessment evidence and tests before dropping its columns. That cannot preserve assessment history after real traffic and conflicts with the repository's data-preservation/blue-green guidance in [AGENTS.md](../../AGENTS.md) and [implementation plan](../learning/IMPLEMENTATION_PLAN.md). This audit does not change the migration; resolve its rollback strategy before a production rollout that could create assessments.

## Recommended next implementation step

Complete **P3-14 shared mode/skill blueprint** with an explicit distinction between target configuration and advertised runnable capabilities, then tackle **P3-15 independent persisted sections and evidence attribution** before vocabulary or Full UI. Preserve the verified grammar Quick path and its contract tests while extracting common lifecycle/evaluator interfaces. In parallel as a design decision (without changing code in Task 01), specify a **generation blueprint** keyed by canonical item, skill, target band, task format and evaluation policy. The user's proposed preference is to store these specifications/prompts and generate fresh question variants rather than rely on fixed exposed wording. Define validation, repeat detection, versioning, item quarantine and a small calibrated anchor set so adaptive thresholds remain interpretable. The existing 48-per-language bank can serve regression/calibration during migration; whether it remains a production fallback is a product decision. Then follow [P3-16..P3-25 order](../learning/IMPLEMENTATION_PLAN.md).

## Open questions requiring product decisions

1. Should generated questions be mandatory for every screening slot, or should reviewed anchor items/fallbacks remain? What latency, AI-key absence and provider failure experience is acceptable? The current bank allows some runs without an AI call, though later exposure may require one ([screeningQuestions](../../apps/learning/backend/internal/learningpath/commands/assessment_items.go)).
2. Who authors and versions canonical objectives, prerequisites, source references/licences and approved generation blueprints? Is `(language, key)` immutable across edits, and what invalidates a previously calibrated question ([D-008/D-013/D-015](../learning/DECISIONS.md))?
3. What evidence threshold and confidence display should constitute a grammar/vocabulary/reading preliminary estimate? How should uncertain/partial results influence a path without presenting `levelReached=A1` compatibility fallback as a measured A1 ([policy](../../apps/learning/backend/internal/learningpath/assessment/policy.go), [finishAssessment](../../apps/learning/backend/internal/learningpath/commands/assessment.go), [D-022](../learning/DECISIONS.md))?
4. May a learner reassess while a path is active, and how should completed topics, prior evidence and due reviews survive a revised plan? The current start/build commands reject an active path ([StartAssessment](../../apps/learning/backend/internal/learningpath/commands/assessment.go), [Analyze.Handle](../../apps/learning/backend/internal/learningpath/commands/analyze.go)).
5. For Full, which skills are required to mark a mode complete as audio/writing capabilities roll out? How long may a section stay paused; can another section or a skill reassessment run concurrently ([D-035–D-037](../learning/DECISIONS.md))?
6. What reviewed content, rubric, consent/retention and accessibility policies gate listening, speaking and pronunciation? TTS and transcript practice alone do not provide these assessment contracts ([P3-22..P3-25](../learning/IMPLEMENTATION_PLAN.md)).
7. **Resolved for the item relation:** migration 0038 names the physical table `learning_knowledge_items` and keeps `kb_items` as a compatibility view. Review the other proposed `kb_*` names before P1 migrations; the renamed table still stores identity/metadata only ([0038](../../apps/learning/backend/migrations/0038_learning_knowledge_items_name.sql), [P1 plan](../learning/IMPLEMENTATION_PLAN.md)).
