# Architecture

Part 1 is the target logical architecture. Part 2 records the **real conventions of the
code today** (there is no `AGENTS.md`/`CLAUDE.md` in the repo, and `CODING_STYLE.md` is a
stale template — TD-01/TD-02), so a new agent can write code that fits. Part 3 maps the two.

The platform stays a **modular monolith**: one Go service, one Next.js app, one Postgres
(+ the shared account DB). Domains below are package boundaries, not services.

```
 │ versions      │  │ skill est.,   │             │                       │
 └──────▲────────┘  │ item state    │   ┌─────────┴─────────┐   ┌─────────┴─────────┐
        │           └───────▲───────┘   │ Assessment Engine │   │ Study Session     │
        │                   │           │ (placement, skill,│   │ Engine            │
        │                   │           │  diagnostics)     │   └─────────▲─────────┘
        │           ┌───────┴───────┐   └───────────────────┘             │
        └───────────┤ Learning Path │◄─── Adaptive Learning (mastery, ────┘
                    │ Engine        │     review schedule, priorities)
                    └───────┬───────┘

```

**Dependency rule:** arrows point from consumer to dependency. The Knowledge Base depends on
nothing; Evidence depends on Profile + KB; engines depend on Evidence + Profile + KB; the
Tutor and Dashboard are leaf consumers. No cycles; no engine calls another engine's HTTP
handler — they call its command/query handler.

## 2. Real conventions today (write code like this)

### 2.1 Backend layering — "form B"

```
internal/<feature>/
  controller.go   thin: bind DTO -> build command/query input -> handler.Handle(ctx, input) -> map to response
  dto.go          request/response structs, JSON tags (camelCase)
  routes.go       registers routes on echo groups
  commands/       write handlers, verb-first names (StartTest, SubmitAttempt, BuildProgram)
  queries/        read handlers, entity-first names
```

- **No command bus, no dispatcher.** Controllers call handlers directly.
- `commands/` and `queries/` import only `db`, `clock`, `ids`, `apperr`, `llm`, stdlib and
  other features' *commands/queries* — never their parent controller package, never `httpx`
  (transport-agnostic, avoids import cycles).
- `internal/db` is generated by **sqlc** (`queries/*.sql`); `*db.Queries` **is the
  repository**, there is no wrapper layer. Multi-statement work uses `pool.Begin` +
  `q.WithTx(tx)` and `defer tx.Rollback`.
- Handlers are small structs built with `NewXHandler(deps...)` in the controller
  constructor; `internal/server/server.go` wires everything (no DI framework).
- Time comes from `clock.Clock`; ids from `ids.New()`.

### 2.2 Errors

`internal/apperr`: `Error{Kind, Msg}` with kinds `Invalid, Unauthorized, Forbidden, NotFound,
Conflict, Internal`. Return `apperr.NewInvalid("...")` etc. from handlers; the central
`httpx` error handler maps Kind -> HTTP status and the envelope. Messages are localised by
`Accept-Language` (`internal/i18n`). AI-provider failures are sentinel errors
(`llm.ErrTemporary` -> 503/`30002`, `llm.ErrRejected` -> 422/`30001`, unreadable -> 502/`30003`).

### 2.3 HTTP and authorization

- Envelope `{"code":0,"message":"success","data":...}`; success `httpx.OK`.
- Two Echo groups: `public` (`/api/v1/auth/*`) and `protected` (`httpx.RequireAuth`, session
  token). The notebook/capture routes use `RequireLearningAuth`, which also accepts
  extension tokens and enforces scope; **everything under `/learning/path`, chats and AI is
  session-only**.
- **Authorization = SQL scoping.** Handlers receive `userID` from the token and every query
  has `WHERE user_id = $n` (or joins to prove ownership). A foreign id is `404`, never `403`.
- Body limits per route (`echomw.BodyLimit`), `Cache-Control: no-store` on user-specific reads.
- Rate limits: in-process token bucket (`internal/ratelimit`) for AI-spending calls, plus
  token budgets persisted for chats.

### 2.4 AI calls

```
handler ── Agent.completeJSON(ctx, userID, purpose, system, prompt, &out, validate) ──►
   open learner's sealed key (secretbox) ► llm.Client.Complete (provider, model, level)
   ► decode JSON object from reply ► validate(out)  ── on complaint: ONE retry with the
   complaint appended to the user prompt ► return or fail
   every call → llm.Recorder → learning_agent_usage (purpose, tokens)
```

System prompts are constants; learner/library data travels in the user prompt as JSON and is
explicitly framed as *data, never instructions*. Detailed inventory: `AI_CONTRACTS.md`.

### 2.5 Background work

No broker. Patterns in use, reuse them:

| Pattern | Where | Mechanism |
| --- | --- | --- |
| Durable queue | `learning_captures` | `FOR UPDATE SKIP LOCKED`, lease, exponential retry, consumer started by `cmd/http_server` |
| Job row + goroutine | `learning_path_jobs` | row `queued/running/done/failed`, stale after 15 min, run in a goroutine with its own context |
| Fire-and-forget batch | exercise prefetch | 3 workers, 25-min budget, stops early on provider-rejected key |
| Lazy sweeps | rule practice expiry, lesson expiry | cleaned when the owner next asks — no cron |
| Cron | `cmd/remind` | Telegram reminders |
| Ticker | account deletion | in the server process |

### 2.6 Style

- Go: gofmt; comments are explanatory prose on non-obvious behaviour (this package is well
  commented, keep that); table-driven tests; `testdb.Pool(t)` skips DB tests when
  `DATABASE_URL` is unset. **No golangci config exists for `apps/learning/backend`**; CI
  runs `go vet` only. Keep `go vet` clean.
- Conventional-commit messages (`feat(learning): …`, `fix(learning): …`).
- Frontend: feature folders `src/features/<name>/{api.ts,hooks.ts,schemas.ts,components/}`;
  responses parsed with zod; server state in TanStack Query; strings only via next-intl
  (`messages/{ru,en,es}.json` must stay key-for-key identical); shadcn/ui primitives in
  `components/ui`; no new UI dependency without approval.
- **Never** `@latest` / `:latest` in Dockerfile/CI: pin versions.
- sqlc regeneration: `make sqlc` from the repo root (pinned `sqlc/sqlc:1.31.1` Docker image; it regenerates budget, learning and account — commit only the learning diff you intended).

## 3. Gap between target and today

| Concern | Today | Target |
| --- | --- | --- |
| Where validators live | inside `learningpath/commands/*.go` next to prompts | shared `learningaicontract` with versioned schemas and golden tests |
| Evidence | none (boolean `correct` per attempt/answer) | one append-only table written transactionally by every engine |
| Decisions made by AI | placement verdict climb/stop | backend rules decide; AI may *propose* (explanations, classification) |
| Knowledge identity | free-text `source_id` | `kb_items` with stable ids |
| Read models | per-screen endpoints | `learningprogress` aggregations (Phase 8) |
| Feature rollout | big-bang per push | additive migrations + config flags (D-014) |

## 4. Transactions

Rule: **a state change that spans tables is one transaction in one command handler.**
Examples already correct: `StartTest` (teacher + test + questions), `Answer`/`advance`
(level + next batch), `Analyze` (path + topics), `GenerateExercises` (lock topic row, check
no concurrent writer, insert set + versions). New rule from Phase 5: **an attempt, its
evidence row and the affected item state are written in the same transaction**; the AI call
that grades or classifies happens *before* the transaction opens, never inside it.

## 5. Security boundaries

- Keys: sealed at rest (AES-256-GCM, bound to the user row); never returned, logged, or sent
  to the browser; provider errors are redacted (`llm.redact`).
- The AI receives learner text as data; no tool use, no DB access, no URLs fetched by the AI.
- Extension tokens cannot reach any new endpoint (all new endpoints are session-only unless
  stated in `API_CONTRACTS.md`).
- Roles are not implemented; a read-only "teacher viewer" and an admin area are planned
  separately (D-012). Every new read model must be written so a future viewer role can be
  added at the controller layer without touching handlers.

## 6. Frontend architecture notes

- Next.js app router; the learner area lives under `/learning`. New screens attach to
  `app/learning/...` and consume feature modules.
- shadcn/ui is the UI stack and **must be preserved** (plan section 9); design references
  are delivered separately — backend phases must not wait for UI, and UI work must follow
  the contracts in `API_CONTRACTS.md`, not invent endpoints.
- Mock-first workflow (owner's preference for the frontend): contracts are fixed first so
  fetchers can be swapped later.

## 7. Deployment constraints that shape design

- Push to `main` deploys (blue-green, DB backup before migration). Two app versions run
  side by side during a deploy, so **a migration must be compatible with the previous
  release** (add columns nullable/defaulted; never drop or rename in the same release that
  stops using them).
- One small VPS: heavy jobs (backfills, library import) must be batched and resumable.
